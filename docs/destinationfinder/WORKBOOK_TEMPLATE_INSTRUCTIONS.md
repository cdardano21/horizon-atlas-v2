# DestinationFinder v3.3 Workbook Template Instructions

## Template decision

Use a **copy-and-sanitize procedure**, not a checked-in empty XLSX generated by an unverified library. The Private-Import-Authorized Next-20 workbook below is the copy-and-sanitize structural reference, while `batch-contract-v3.3.json` is the machine-readable sheet/header contract and names the later Visual-Parity-Enriched artifact as its current contract/readiness proof. This avoids losing formulas, styles, validation lists, column order, workbook relationships, or control-sheet content.

Never edit or overwrite the authorized reference workbook.

## Safe creation procedure

1. Verify the reference hash before opening it.
2. Copy the reference to a new batch directory and descriptive candidate filename. Keep the original read-only.
3. Confirm the copy opens without a repair prompt.
4. Preserve all 48 sheet names, order, hidden state, column order, styles, validations, formulas, and workbook-level names.
5. Retain reference/control content in `README`, `CATEGORIES`, `SCORING_DIMENSIONS`, `STAY_MODES`, `SCHEMA_INDEX`, `PREMIUM_REQUIREMENTS`, `IMPORT_CONTRACT`, `VALIDATION_RULES`, and `DATA_DICTIONARY` unless a separately authorized schema revision changes it.
6. Retain the `CHANGELOG` header and add a new truthful batch entry; do not copy the Next-20 batch history as though it described the new batch.
7. Clear all old destination-scoped rows from data sheets. This includes `DESTINATIONS`, every module containing `destination_key`, `PILOT_STATUS`, `IMPORT_MANIFEST`, and `DESTINATION_ALIASES`.
8. Clear batch-specific rows/values from `WORKBOOK_METADATA`; repopulate schema, workbook name, destination count, validation state, source policy, dates, methodology, and preservation status for the new artifact.
9. Populate only the approved destination keys. Never use reference rows as placeholders.
10. Rebuild `CLIMATE_MONTHLY` formulas so each destination/month points to that destination's exact `DESTINATION_FACTS` rows. Do not retain reference row coordinates blindly.
11. Recalculate formulas in a compatible spreadsheet application and save cached results.
12. Reconcile `IMPORT_MANIFEST` expected counts to actual rows.
13. Save to a new candidate path, compute SHA-256, and treat those bytes as immutable during validation/review.

## Key construction

- `destination_key`: permanent approved canonical key.
- `slug`: stable canonical route slug, normally equal to the key for new destinations.
- Child keys: stable semantic keys prefixed with the destination key; do not derive identity solely from row number.
- `DESTINATION_ALIASES`: exact reviewed aliases only; one active alias resolves to one key.
- Composite monthly identity: exact destination key plus month.
- Never renumber existing stable keys merely because display order changes.

## Formula safety

The reference workbook contains 960 formulas, all in `CLIMATE_MONTHLY` columns C-F (`avg_high_c`, `avg_low_c`, `rainfall_mm`, `humidity_pct`). A safe template operation must:

- preserve formulas as formulas, not pasted cached values;
- update row references for the new destination fact layout;
- retain source facts, units, and verification;
- recalculate before validation;
- inspect cached values for all 12 months per destination;
- reject cross-destination references, blanks caused by stale caches, and divide-by-zero/error cells.

## Authoring order

1. Identity, metadata, manifest, aliases, and status.
2. Sources and evidence ledger.
3. Hard-gate and U3-R5 facts.
4. Climate source facts and formulas.
5. Relocation modules.
6. Neighborhoods, places, resources, and media.
7. Reality checks, checklists, events, and optional depth modules.
8. Counts, verification dates, formula recalculation, and final workbook hash.

Use `AUTHORING_DATA_REQUIREMENTS.md` for every exact field and minimum count.

## Preflight

For an unregistered candidate:

```bash
npm run --silent validate:destination-batch -- \
  --workbook data/<batch>/<candidate>.xlsx \
  --expected-keys key-one,key-two \
  --json
```

For a frozen registered candidate:

```bash
npm run --silent validate:destination-batch -- \
  --workbook data/<batch>/<candidate>.xlsx \
  --registry-id <registry-id> \
  --json
```

Passing validation does not authorize import. Archive the report and hash, resolve warnings, and continue through the playbook's separate approval gates.

## Template rejection conditions

Reject and recreate the candidate if any sheet/header/order differs, Excel reports repairs, reference destinations remain, formulas point to old rows, metadata claims unearned readiness, manifest counts drift, aliases are ambiguous, or a source/control sheet was rewritten without explicit schema authorization.
